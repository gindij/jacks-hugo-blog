The challenge of multimodal distributions in ML

15 February 2025   716 words   ~4 mins

Introduction

In this post, I want to write about multimodality – though not in the sense that the AI world has been buzzing about recently. One way to build decision making systems is to show the system many of examples of desired behavior during the training process. But this introduces an important problem: that there are many ways of accomplishing a given task! Training certain kinds of (widely-used) machine learning methods on multiple different ways of accomplishing the same task could result in some kind of weird – and possibly invalid – averaging that leads to suboptimal, at best, and, at worst, unusable systems.

For the rest of this post, we’re going to introduce multimodality with some simple examples, see why it presents a problem for deterministic machine learning algorithms, and then discuss some approaches for training decision making systems that can work around some of those pitfalls.

What is multimodality?

Let’s say we’re trying to fit this data with linear regression.

Using simple linear regression, we’d find a line like this one.

What it means to “find a line” in this context is to find $m$ and $b$ that minimizes the the mean square distance between the collection of training points and the line. Now suppose I wanted to generate some $y$ values for some new values of $x$. In other words, how could I use the parameters $m$ and $b$ in a generative capacity?

One simple way to do it would be to assume that the errors come from a mean-zero normal distribution and calculate a variance $\sigma^2$ that captures the spread of the training points around the line. With this value of $\sigma^2$, we can generate new points by

  1. picking a value of $x$
  2. sampling $y \sim \mathcal N(mx +b, \sigma^2)$

That is, we use $mx + b$ as a starting point, then add some noise to produce our $y$.

As you might imagine, this strategy would actually work pretty well at generating plausible points like the ones in the collection shown in the first figure.

But what about if we started with data like this?

If we fit a model to the points in this example and used the same procedure to generate new points, what would happen? Well, if we sampled $y$s for $x$s around 3, we’d probably produce a large number of points where there aren’t any in the actual dataset we’re trying to model. To crystallize what messes things up here, let’s look at the cross section of $y$ values around $x=3$.

When we say that the data distribution is multimodal, we informally mean that there are more than one point around which data are clustered. The normal distribution we sampled from in step 2 above is unimodal, since it is centered around $mx + b$ alone; it would be difficult for a simple generative process like the one we designed to reproduce the true shape of this data.

Why is it a problem?

When we train decision making systems to perform tasks of interest, there might be more than one way to accomplish the task. Take this very simple example: Suppose we want to train a robot to navigate around obstacle like the one shown in the image below using correct demonstrations.

In this example, there are two modes around which the correct examples cluster: paths that pass above and below the obstacle. If we learned a unimodal policy (a way to turn observations into actions), can you see what might happen? (Pause and think it through before continuing.)

A unimodal policy here would center around the average of the behaviors shown in the dataset, which would be to… try to move straight through the obstacle. Since this action is not valid, the robot would freeze.

In the real world, there are many correct ways of accomplishing the same task. If we collect demonstrations from many different humans, not only might we find different ways of doing things, we should expect multimodality in our dataset. What types of model architectures can we use to avoid this sort of undesirable averaging that occurs when we learn unimodal action distributions?
